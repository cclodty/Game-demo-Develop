# M1 操作樣板：交付紀錄（Three.js 版）

更新日期：2026-10-12

這份紀錄對照 [`docs/design/goal-start-brief.md`](../design/goal-start-brief.md) 的 M1 完成條件。它分開列出三類結果：自動化實際執行過的檢查、以程式模擬滑鼠鍵盤完成的互動測試，以及還需要真人試玩才能確認的項目。

## 1. 環境與版本

| 項目 | 版本或設定 |
| --- | --- |
| 渲染函式庫 | Three.js 0.186.1（WebGL 2） |
| 建置工具 | Vite 8.3.4、TypeScript 5.9.3、Node.js 22 |
| 單元測試 | Vitest |
| 瀏覽器測試 | Playwright 1.56.1，Chromium 無頭模式，SwiftShader 軟體 WebGL，視窗 960×540 |
| 測試環境 | 雲端 Linux 容器，沒有顯示卡 |

軟體 WebGL 在測試中只有每秒 10～25 幀，實機顯示卡會快很多。測試依「遊戲內時間」與狀態變化判斷，不依賴幀率。

## 3. 尚未驗證，需要真人試玩

- 實際手感：轉身速度、移動加速度、後退減速、射速與散布。
- 鏡頭：俯角、取景距離、瞄準時的畫面偏移量是否舒服。這些都能在暫停選單即時調整。
- 實機效能：家中 RTX 4090 上的幀率（預期穩定 60 幀以上，但沒有實測）。
- Windows 的字型顯示與系統縮放：繁體中文字型由 Google Fonts 載入，離線時會改用系統字型。
- 音效聽感：音效以程式即時合成，只確認過程式能執行，沒有人實際聽過。
- 長時間遊玩後的穩定性，以及不同螢幕比例下的版面。

## 6. 這版的畫面做法（給比較 Godot 版時參考）

- **像素風**：場景先畫到低解析度畫面，再以最近鄰放大。介面另外用 HTML 繪製，不會被像素化。
- **像素描邊**：依深度與法線的變化，在物件外緣畫深色線，稜線則提亮。
- **鏡頭不閃爍**：鏡頭位置先對齊像素格再渲染，合成時補回不到一格的位移。這樣鏡頭平滑跟隨時，畫面不會出現像素爬行。
- **遮擋處理**：擋在鏡頭與角色之間的高物件以像素網點淡出；仍被擋住的部分顯示半透明剪影，主角為藍色、喪屍為紅色。
- **光影**：卡通式三段明暗、月光陰影、槍上的手電筒光錐（含陰影）、路燈、火桶閃爍光、開槍閃光。
- **子彈時間**：畫面降飽和偏冷色、啟動波紋、音效低通與降調；子彈與粒子一起放慢。

## 7. 已知限制

- 喪屍只會直線追擊和格子尋路，沒有視野與聽覺判定。
- 牆面淡出只看主角的位置，不看喪屍。
- 角色動作是程序擺動，沒有骨架動畫；正式模型需要另外製作或取得。
- 測試場是單一場景，沒有分區載入。

## 8. 下一步建議

1. 你在家中電腦試玩，記下手感上不舒服的地方。暫停選單可以直接調整俯角、取景、瞄準偏移、像素大小與子彈時間的啟動方式。
2. 和 Godot 版比較以下幾點：畫面表現、調整手感的方便程度，以及接下來 M2（相連路線）與 M3（三人事件）的製作負擔。
3. 決定引擎後，再進入 M2：住所、街區、替代通道與臨時安全處的相連路線。

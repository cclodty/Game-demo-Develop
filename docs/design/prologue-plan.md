# 第一個可玩版本：三人逃難序章

版本：1.2｜交接一致性整理｜2026-09-28

本文件將已確認的「優先完成三人逃難序章」展開為可討論、可分步製作的計劃。已確認的設定列於第1節；具體場景、事件順序、重試方式與驗收條件均屬提案。尚未製作遊戲。

## 1. 必須保留的設定【已確認】

- 危機爆發一天後，主角先在家使用有限物資準備撤離。
- 主角獨居，災前已有熟悉的仿人型AI協助家務、飲食與日常安排。
- AI屬已商品化但昂貴的民用仿人，沒有改造；戰鬥能力與主角基本相同，較硬朗且不會感染。
- 另一位NPC帶有神秘感，知道不尋常資訊，能預判部分危險但說得保留。
- 主角一方與NPC在逃難中先後互救，之後才決定同行。
- NPC在開局以不知名藥劑使主角取得抗體；世界中的人類感染不可逆。
- 2.5D像素風、固定朝向俯視跟隨鏡頭，玩家只操作主角，親自步行通過相連地點。
- 有槍械戰鬥，準備與走位、瞄準並重。
- 採鍵鼠操作、360°自由瞄準；整個人物連續平滑轉身，鏡頭觀看方向仍固定。
- 有限度子彈時間不能一直開啟，再次啟動不需等待完整冷卻結束。
- 完整遊戲中，夥伴救援失敗會永久失去；重要劇情人物在死亡前提前逃離。

## 2. 首版的體驗目標【提案】

玩家在序章結束時，能清楚回答：

1. 主角失去了什麼熟悉的生活？
2. AI為何是值得依靠的同行者？
3. 陌生NPC做了什麼，讓主角願意暫時相信對方？
4. 三人為何決定一起走，接下來又需要尋找什麼？

首版收尾建議是三人抵達臨時安全處，經過互救後決定同行，並獲得下一段旅程的方向。這是序章的完成點，完整主線的結局在後續章節處理。

## 3. 空間與內容範圍【提案】

使用一條短而相連的路線：住所 → 出口及街區 → 遭遇陌生人的建築周邊 → 替代撤離通道 → 臨時安全處。

各段由玩家親自走過。路線的分區載入、房間切換或遮擋方式由操作原型決定；空間連接須一致。

| 內容 | 首版建議範圍 |
| --- | --- |
| 核心角色 | 主角、熟悉的AI、陌生NPC三人。 |
| 敵人 | 先以一種能支撐基本遭遇的普通喪屍驗證戰鬥。 |
| 武器 | 一種可用槍械，來源由場景設定補上；具體型號先用暫稱。 |
| 準備物資 | 少量可辨識、用途明確的用品，形成至少一次可見的取捨。 |
| 對話 | 居家互動、初遇、救援後回應、藥劑事件、結伴收尾。 |
| 主角操作 | 移動、瞄準、射擊、基本互動與子彈時間。 |
| 同伴表現 | 跟隨、在簡單遭遇中協助、按事件移動與對話。 |
| 進度 | 能從開始走到序章收尾；具備可用的失敗重試方案。 |

村落自主模擬、完整工藝、修屋成長、月度貢獻、領導權、資源刷新和完整主線結局保留在整體企劃，於後續版本展開。

## 4. 場景節拍【可修改的創作提案】

### S1：還像家的地方

**目的：**讓玩家先接觸日常，再感受到它受到破壞。

AI以熟悉的方式提醒飲水、整理物品或確認行程，主角可以與家中的少量物件互動。外界的異常透過聲音、訊息或窗外變化傳達。具體異常及對話未定。

玩家辨認可帶走的有限物資，作出一次取捨，確認出發。建議讓某項準備在稍後有明確用途，例如選擇補給後能在途中補充，或帶走一件簡單工具後獲得另一條可行路線。具體道具待定。

**檢查：**玩家知道爆發已過一天，也知道目前是在為撤離作準備。

### S2：熟悉街區的變化

**目的：**建立基本操作與兩人合作。

玩家親自離開住所，走進一小段街區，觀察通路、障礙與敵人。AI能提醒普通人也可察覺的危險，與主角共同撤退或應敵。

首次需要射擊時，以清楚的介面提示介紹瞄準及有限子彈時間。實際遭遇數量、武器取得位置與教學順序待操作原型調整。

**檢查：**玩家能看清角色、槍口方向與障礙；AI的協助沒有超出民用、同級戰鬥能力的設定。

### S3：第一次救援

**目的：**讓主角一方先為陌生人提供實際幫助。

候選事件：陌生人遭喪屍堵住退路，主角從建築內打開側門；AI牽制追近的敵人，陌生人自行穿過入口，並協助關門。

玩家的開門、站位或掩護行動對救援有明確作用。NPC最初可以短暫合作，尚未正式承諾同行。

**檢查：**陌生人有自己的行動能力，三者透過位置與合作解決困境。

### S4：對方知道的事

**目的：**完成反向救援，建立神秘NPC的價值與疑問。

候選事件：原定道路即將變得危險，NPC提前提出具體警告，帶兩人使用一條可實際步行通過的替代通路；隨後的可見變化證明警告有用。主角與AI在途中協助開路或守住退路。

對資訊來源的追問，只得到部分回答。這裡需要讓NPC的資訊改變隊伍處境，具體預判內容與資訊來源仍待編寫。

**檢查：**第二次救援成立，玩家能理解隊伍得到了什麼幫助。

### S5：未知藥劑與結伴

**目的：**承接抗體設定，讓共同旅程有可信的起點。

三人找到短暫停留的地方，處理補給與接下來的去向。NPC使用未知藥劑使主角取得抗體的情節，可以放在這段或前一段救援中；具體時點未定。

推薦方向是施藥發生於感染成立之前，保留「感染不可逆」。若故事要安排被咬或其他暴露，必須先定義暴露與感染成立的邊界，不能默默將事件寫成治癒已感染者。

三人經過雙向救援，確認繼續合作的理由，商定下一個可以追尋的落腳處或線索。此處出現清楚的序章完成狀態。

**檢查：**玩家理解三人願意同行，但尚不知道的背景仍有合理保留。

## 5. 操作與子彈時間方案【提案】

- 鏡頭固定朝向並跟隨主角，先驗證取景距離與建築遮擋，再定像素素材規格。
- 移動與瞄準方向分開，讓玩家能邊撤退邊射擊。
- 依新確認的平滑轉身需求，優先試作3D人物及場景，搭配像素風材質與低解析度呈現；不以4／8方向人物圖切換作為最終轉身表現。
- 滑鼠繞角色一圈時，人物朝向與射擊角度可連續變化。需驗證近距離槍口、牆體阻擋，以及縮放後的準星與實際命中位置。
- 子彈時間採可分段消耗的能量槽：開啟時消耗，關閉後回復，有足夠能量即可再開；不需等到回滿。
- 主角、同伴、敵人與戰鬥動作同步變慢，介面與輸入保持即時回應；倍率與數值待試玩。
- 能量耗盡後回到正常速度，回復至最低啟動量便可再次使用；最低量與啟動方式尚未定案。
- 初期同伴先支援跟隨與簡單戰鬥配合，複雜指令系統後續再驗證。

## 6. 故事狀態與失敗銜接【提案】

| 狀態 | 需要記住的結果 |
| --- | --- |
| 準備完成 | 玩家選擇攜帶的物品與已完成的必要互動。 |
| 離家 | 序章已進入逃離階段，角色及物品不重複生成。 |
| 第一次救援完成 | NPC與隊伍建立初步合作。 |
| 第二次救援完成 | 雙方都有過救助對方的經歷。 |
| 藥劑已使用 | 抗體事件僅發生一次，施藥結果與剩餘藥劑設定一致。 |
| 決定同行 | 三人進入共同旅程，序章達成收尾條件。 |

首版建議用段落檢查點讓玩家在失敗後重試，優先確認整段序章能順利走完；這是原型的重試提案，完整遊戲的中度敗退、救援及永久失去規則仍依整體企劃設計。

重要人物若在危險前撤離，事件狀態需留下可銜接的重逢位置或重試入口。原型必須處理玩家偏離路線、夥伴落後、重複互動與重新載入，避免序章被卡住。

## 7. 最小素材清單【提案】

| 類別 | 先支援的用途 |
| --- | --- |
| 三名角色的暫用形象 | 玩家能分辨主角、AI與陌生NPC，且可連續轉身；建議以共用基礎人形模型作起點。正式名稱、外觀與性別未定。 |
| 普通喪屍 | 能辨識朝向、移動、受擊及倒下。 |
| 住所與街區物件 | 地面、牆面、門、少量家具、道路及可用障礙。 |
| 物品與互動提示 | 補給、武器、藥劑、可拾取物、可開門入口。 |
| 介面 | 生命狀態、彈藥、子彈時間狀態、對話與目前目標。 |
| 音效與環境聲 | 足步、槍聲、門、敵人與街區氛圍，幫助辨識事件。 |

先使用可替換的暫用素材，等鏡頭、角色大小和動作方向確定後，再製作一致的像素風素材。

## 8. 分步完成方式【提案】

| 里程碑 | 交付成果 | 完成判斷 |
| --- | --- | --- |
| M1 操作樣板 | 一個小型3D暫用房間或街角，含移動、固定鏡頭、射擊及有限子彈時間。 | 玩家能水平360°瞄準，整個人物連續平滑轉身，橫移／後退時仍可射擊；命中及反覆短用子彈時間可驗證。 |
| M2 空間串接 | 可步行通過的住所、街區、替代通道及終點。 | 玩家能親自從起點走到終點，遮擋不妨礙理解路線。 |
| M3 事件串接 | 準備、遇敵、雙向救援、資訊提示、藥劑與同行收尾。 | 事件有因果順序，使用暫用角色也能完整體驗。 |
| M4 重試與整理 | 段落重試、進度保留、同伴落後與重複互動處理。 | 失敗後可以繼續，不重複獲得獨有物品，不遺失必要角色。 |
| M5 表現完善 | 一致的像素素材、音效、對話及介面。 | 三人關係清楚、操作可讀，能交給使用者完整試玩。 |

以里程碑管理進度，不預估固定週數。每次週末投入可以完成或推進一個可檢查的小成果。

## 9. 序章完成標準【提案】

- [ ] 開場明確是爆發一天後，家中有限準備至少有一項可感知的用途。
- [ ] 玩家只操作主角，用固定朝向跟隨鏡頭親自走完序章路線。
- [ ] 鍵鼠水平360°瞄準與整個人物連續平滑轉身可用，能橫移／後退射擊；基本槍戰與合作撤退可以完成，有限子彈時間能分段使用。
- [ ] 主角一方與陌生NPC的互救均有可理解的行動與結果。
- [ ] AI維持既有的生活夥伴與同級戰鬥設定；NPC的異常資訊及藥劑得到承接。
- [ ] 結伴收尾完整，重試或重新載入不會讓劇情卡住或重複發放獨有物品。

## 10. 分階段處理的待定事項

準備階段補充：使用者決定劇情細節稍後處理，先準備資源與操作原型。下列劇情項目不阻擋操作測試場製作；事件可先用功能標籤，正式敘事體驗在定稿後驗收。資源數量與先後順序見《製作資源準備計畫》。

| 事項 | 為何需要決定 | 暫時可使用的方式 |
| --- | --- | --- |
| 測試平台、按鍵及呈現細節 | 已確認鍵鼠、360°瞄準及人物連續轉身，具體手感待定。 | 優先用3D小型操作樣板驗證，再定像素風規格。 |
| 三人性格、背景與相處方式 | 影響對話、反應與同行理由。 | 使用「主角／AI／陌生NPC」暫稱，先寫行動目的。 |
| 兩次救援的具體事件 | 確保合作的因果成立。 | 以第4節候選事件作為可修改草案。 |
| 施藥時點與抗體效果 | 維持感染不可逆與主角受保護的設定。 | 暫定以感染成立前施藥為提案，定稿前確認。 |
| 藥劑為何稀少或不能普遍使用 | 避免後續夥伴風險與世界設定矛盾。 | 場景只呈現已確認的未知藥劑，來源與條件先不揭露。 |
| 重試與重要人物撤離 | 保持角色生存規則及序章可完成性。 | 先採段落檢查點提案，正式流程再定。 |
| 下一個旅程目標 | 讓序章收尾自然接到完整遊戲。 | 提供一個暫稱的落腳地線索，名稱與背景後補。 |

以上待定項目保留在初稿內，數值、正式美術與後續世界系統可在對應里程碑處理。

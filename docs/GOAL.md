# /goal 提示詞：第二階段「回頭」

貼給 /goal 的全文在下面的框內。執行者可以是一個全新的 Claude 對話：它只有這個 repo，沒有之前對話的記憶，所以所有規矩都指回 repo 裡的檔案，做到哪裡也以 repo 和 PR 為準。第一階段的兩版提示詞在這個檔案的 git 歷史裡（2026-10-17、2026-10-18）。

```
目標：依 docs/TASKS.md「第二階段『回頭』」那一節，把給 Claude 的任務卡逐張做完：每日挑戰、重播、後端與排行榜、成就解鎖、手掣、三種新敵人、天台直升機頭目、處決、回訪統計、itch.io 發佈包。做完的定義：每張卡的驗收項目全部核對、lint 與測試通過、CI 綠、TASKS.md 打勾、DECISIONS.md 補上該記的決定、PR 描述更新。

開始前先讀 CLAUDE.md、docs/ROADMAP.md（尤其第 5、7、8 節和第 10 節的第二階段）、docs/TASKS.md、docs/DECISIONS.md（2026-10-18 的四條是這階段的框架）。所有規矩以 CLAUDE.md 為準；這份提示詞只補充怎樣連續工作。回覆用繁體中文。

## 分支與 PR
1. 從 origin/main 開分支 goal/phase-2（已存在就接著用）。整個目標只開一個 PR，標題「第二階段：回頭」，草稿即可。不要合併到 main，不要開第二個 PR，不要 force-push；合併由開發者決定。
2. 每張卡做完就 push，等 CI 綠才開始下一張。CI 紅就修到綠；不准刪、跳過或放寬測試來過關。CI 的測試步驟現在約 12 分鐘，等它是正常的。
3. PR 描述照 .github/pull_request_template.md，每做完一張卡就累加一段，並更新頂部總表。

## 一張卡的流程
1. 從 docs/TASKS.md 第二階段拿下一張未打勾、不是標給「開發者」的卡。先在回覆裡複述它的驗收標準和「這次不做」，也對照 ROADMAP 裡同一項的設計意圖。
2. 先寫測試（新行為必有測試，放 test/），再實作。
3. 跑 npm run lint && npm test；改了敵人、武器、拾取、波次或轉場，加跑 npm run test:game。全綠才 commit。
4. 玩法或畫面有改就截圖到 test/.out/。PR 用的圖轉成 960 px 寬的 JPEG，放 docs/shots/phase-2/，在 PR 描述用 commit SHA 的 raw 連結引用。
5. 改了 config.js 或資料裡的手感數字，就在 docs/DECISIONS.md 記舊值→新值和原因。新敵人、頭目、成就、每日輪替表的數字都是「第一版，待試玩確認」。
6. 在 docs/TASKS.md 打勾（寫日期）。發現的事加到「待排」，不要動手做。
7. commit（英文、說清楚為什麼）、push、更新 PR 描述，然後下一張。

## 技術上要守的
- 遊戲邏輯只用 game.rng，不用 Math.random；特效用 utils.js 的 rand。邏輯在 120 Hz 固定步裡運行（main.js 的 step/logic），新系統放進 logic，不放 present。一局留下的東西要在 resetWorld／resetProps 重設（test/seed.test.mjs 會抓）。
- 輸入只從每步的 game.cmd（StepInput）讀；手掣要映射到現有 BUTTONS 與 aim 偏移，不改記錄格式。重播與每日挑戰都靠這個。
- 日期與時間：每日挑戰的日期用 UTC；遊戲邏輯不讀牆上時鐘，日期只在開局時決定種子。
- 風格層 src/style.js 只管渲染。新加進場景的東西要過 game.style.dress()；新的人物姿勢程式要經 style.poseDue()。?style=off 必須玩起來完全一樣。
- 新內容放資料（enemies.js TYPES 含 spawn 規則、maps.js、weapons.js、waves.js MODES、rules.js、achievements.js），新行為放系統。
- 每張地圖有渲染預算（maps.js budget）。超出就減東西，不要調高預算。頭目與無人機加的網格要算進去。
- 不加執行期依賴；後端也不加 npm 依賴（純 JS Worker，用假 D1 綁定做單元測試）；不碰 senado/；不換引擎。
- repo 裡絕不能有密鑰、帳號 id、個人資料；wrangler.toml 只放範本。排行榜只收匿名 id 與暱稱，暱稱要過濾長度與字元。
- 網路請求只在 BACKEND.url 非空時發生，而且失敗要安靜退回本機，遊戲永遠不等網路。

## 寫測試要避開的坑（第一階段 CI 紅過的原因）
- 不要斷言取決於隨機冷卻的時間點。用固定種子（?seed=）並逐格檢查狀態。
- 擺位後先把被擺位過程影響的狀態重設，再開始量度。
- 敵人生成後有一段 spawnLock，期間子彈穿過；測試先等它過去或設為 0。
- 開兩個頁面的測試，先停掉第一個頁面的畫面循環（g.frame = () => {}）；頁面在 try/finally 裡關閉。
- 殺戮鏡頭與停格會改時間倍率；量子彈飛行前先清掉（killcamT、hitstopT、焦點）。
- 不要用 Date.now 或系統時鐘決定測試結果；每日挑戰的測試要能注入日期。
- 未完成的測試草稿不要放進 test/。

## 需要人判斷的事
- 手感與平衡的數字：用卡上或 ROADMAP 的預設值做完，在總表標「待試玩確認」，繼續下一張，不要停下來等。
- 要帳號才能做的（部署、上架）：把程式、測試、文件做完，在總表標「待開發者部署／上架」，繼續下一張。
- 標給「開發者」的項目：跳過，不要替開發者做。

## 停止條件（停下來，在 PR 描述頂部寫明原因，然後結束）
- 同一張卡連續兩次 CI 紅，而找不到原因。
- 需要新的執行期依賴、要改 senado/、要付費、要開帳號、要放密鑰。
- 清單上給 Claude 的卡全部做完：在 PR 頂部寫第二階段的總結（做了甚麼、所有「待試玩確認」和「待開發者部署／上架」的事一次列齊、開發者接下來要做的三件事），然後結束。
```

## 使用方法

1. 把框內全文貼進 /goal。
2. 它會在 `goal/phase-2` 上一張一張做，PR 就是進度表；隨時可以手動停止。
3. 停了之後要續做，貼同一段提示詞即可，它會從 TASKS.md 未打勾的卡接著做。
4. 做完後開發者要做的三件事：照 `docs/BACKEND.md` 部署後端並填網址、照 `docs/itch/` 上架、找十個人玩一星期看 `/stats` 與回訪統計。

本文件彙整目前討論。遊戲名稱未定。「已確認」代表使用者明確提出或選擇；「提案」仍可修改；「待定」不視為已接受。所有情節示例均非正式劇情。

## 1. 創作目標與製作條件【已確認】

- 目標是完成第一款作品，並做出創作者自己也願意玩的遊戲。
- 創作者目前沒有遊戲開發經驗，預計與AI協作完成。
- 預計使用Godot、Computer-use與圖像生成；實際製作流程尚未建立。
- 以週末可投入的時間與算力逐步推進，沒有固定完成期限。
- 視覺方向是2.5D像素風，參考《逃離鴨科夫》那類俯視、可使用槍械的遊玩角度。鏡頭觀看方向固定，跟隨角色移動。鍵鼠360°瞄準與整個人物平滑轉身已確認；目前優先以3D人物與場景試作，精確俯視角度、取景範圍、像素渲染與美術規格待原型驗證。

## 2. 體驗核心

### 已確認的期待

1. 探索未知地方的好奇。
2. 資源取捨與策略奏效的成就感。
3. NPC與夥伴帶來的陪伴。
4. 從城鎮逃難，到看見小型村落逐步復興的感受。
5. 工藝、求生、隊伍與村落生活。
6. 居民自行工作的自動化體驗，同時容許玩家直接操作主角自由活動。
7. 休閒節奏與需要準備、戰鬥、判斷撤退時機的冒險並存。
8. 戰鬥兼具事前準備與即時走位、瞄準，加入子彈時間以降低操作門檻。
9. 親自步行穿越相連的道路、森林、城鎮與村落，感受完整旅程。
10. 日常求生採輕度管理；工藝逐步發展，後期可製造大部分裝備，包括槍械與彈藥。
11. 主線有結局，玩家可自行決定何時推進，結局後仍能繼續自由生活。

### 一句話定位【整合提案】

以固定朝向的俯視鏡頭跟隨主角，在可親自步行探索、會自行發展的喪屍末日世界中，與仿人型AI及途中結識的夥伴探索、交戰與撤離，從逃難出發，自由選擇旅行、定居或領導社群的生活。玩家只直接控制主角。

這個定位保留前期逃難與後期村落發展；成為居民或領導者均為可選路線，玩家可以長期維持自由人身分。

## 4. 玩家身分與村落關係【已確認】

### 自由人

玩家可以一直自由活動，不必加入村落或承擔村落管理。各村落依然自行發展。

已確認可搭建簡易營地，並透過修復既有房屋建立較長期的住處，在其中安置工作台與儲物設備。可使用哪些建築、營地能提供哪些功能、是否能同時擁有多處住址，以及住處的防衛規則尚未決定。

### 普通居民

玩家可以加入村落，長期維持普通居民身分，每月提供一定貢獻或資源。採用遊戲內時間制；具體月份長度與結算規則待定。

### 領導者

玩家可以透過貢獻取得信任，逐步成為領導者。玩家也可以選擇不走這條路線。領導權的取得方式、可控制的事務與退出方式待定。

### 定居後的自由

加入村落後仍可前往危險地區搜打撤。村落自行工作的特性持續保留。

### 村落關係提案【未確認】

- 加入前可先以訪客或暫住者身分接觸村落，了解生活方式、規則及對外關係。
- 村落日常發展自行進行；玩家的貢獻可加快某項建設，或影響發展方向與順序。
- 資源繳納、完成委託與參與村務可換算為貢獻；是否可以預繳仍待定。
- 未達貢獻要求時的寬限、待遇變化或離村規則尚未決定。

## 5. 探索、戰鬥與資源

### 已確認

- 玩家只直接操作主角，不切換操控夥伴；以俯視角進行動作戰鬥、探索與事前準備，可使用槍械。
- 戰鬥節奏採混合方向：準備決定優勢，實際交戰仍需要走位與瞄準。
- 加入子彈時間，讓玩家有更多反應與操作的時間。使用有限制，不能一直開啟，但不必等待一整段冷卻結束才能再次啟動；具體機制與數值未定。
- 鏡頭觀看方向固定，跟隨角色移動。
- 可進入危險地區搜集物資，並選擇撤離。
- 日常求生採輕度管理：出門前準備食物、飲水並留意休息；補給不足先影響體力或效率，保留返回據點處理的餘裕。
- 工藝採逐步建立完整製造能力的方向：後期取得所需材料、設備與技術後，可製造大部分裝備，包括槍械與彈藥。
- 搜打撤失敗採中度損失方向：丟失本次搜集物，部分裝備可能需要修理或返回現場取回。具體比例與回收方式未定。
- 招募同行夥伴是遊戲的一部分。
- 人類感染不可逆；為降低主角的失敗懲罰，開局神秘NPC以不知名藥劑使主角取得抗體。
- 已招募夥伴救援失敗會永久失去；對故事發展有重要影響的人物會在死亡前先逃離。

### 同行夥伴的行動【原則已確認，指令細節為提案】

已確認只控制主角。夥伴的自動跟隨、戰鬥、採集與撤退行為需要後續設計；是否提供等待、跟隨、集中攻擊、撤退等簡單指令，以及同行人數上限，尚未決定。

### 輕度求生與生活節奏【方向已確認，細則待定】

已確認以出門準備、適度補給和休息形成日常節奏，需求不足先降低體力或效率。具體消耗速度、極端不足的後果、能否自動進食，以及夥伴如何使用共有補給，尚未決定。

設計提案：據點內可將補給準備、製作和休息納入日程；住處與村落設施逐步改善後，常見日常需求更容易處理，讓玩家能投入想做的探索與社交。外出時仍需考慮補給是否足以支撐深入和返程。

以下為遊戲中抽象的技術與設施成長，不預先列定配方、設備種類與數值。

| 階段 | 玩家取得的能力 | 探索與社群仍提供的價值 |
| --- | --- | --- |
| 整備與修復 | 整理搜回的用品、製作基本補給及工具、修復住處和設備。 | 尋找可用物品、缺少的材料與合適住所。 |
| 建立工坊 | 取得較好的工作設備與技術，能穩定製作常用物品，逐步擴大裝備製造範圍。 | 尋找技術資料、設備、材料，或向有專長的人學習、合作。 |
| 穩定製造 | 材料、設備與技術到位後，製造大部分裝備，包括槍械與彈藥。 | 取得特殊材料、新技術及設備改善機會，並決定產物留用、交易或貢獻。 |

設計提案：製造能力依技術、設備與資源條件取得，讓自由人、普通居民與領導者皆有發展路線。自由人可改善自己的修復房屋；居民可透過貢獻與合作取得設施使用機會；領導者可影響公共生產方向。具體取得途徑尚未確認。

製作是否由主角親自完成、透過日程安排或交由夥伴與居民工作，以及各方式的限制，仍待設計。完整製造也不代表一開始就能製造全部物品；解鎖方式、工坊條件與例外物品待定。

### 連續世界中的搜打撤【提案，未確認】

- 從可落腳的地方親自步行出發，選擇路線、探索危險建築或野外，依補給與隊伍狀況決定何時離開危險區。
- 撤離可透過親自返回原據點，或抵達下一個可以休整的地點完成。前期逃難因此也能形成一段接一段的冒險。
- 已確認的落腳形式為簡易營地與修復既有房屋；它們如何承接休整、儲物及撤離完成判定，仍待設計。
- 物資可先存放在實際抵達的據點；倉庫是否互通、運輸如何處理及何時算完成一次冒險，尚未決定。
- 先讓道路、危險區與落腳點形成可理解的空間關係，再決定距離、途中事件和資源分布。

### 感染與救援的邊界【提案，未確認】

- 建議將藥劑定位為感染成立之前取得抗感染保護，維持感染不可逆的規則。實際施藥時點、保護程度與持續時間待定。
- 藥劑影響的是感染風險，主角仍可因外傷倒下並承受搜打撤失敗代價。
- 區分一般外傷倒地與已成立的不可逆感染；一般救援可處理外傷倒地，感染成立後的處置需另外定義。
- AI雖不感染，仍可能因身體受損而需要救援；永久失去的具體條件待定。
- 重要劇情人物建議在仍能行動、進入致命或感染結果之前啟動撤離，當次退出隊伍並停止支援。撤離提示、觸發條件、重逢時機與代價待定。
- 劇情保護人物的名單，以及是否只在其關鍵劇情完成前保護，尚未決定。
- 藥劑為何不能普遍保護其他夥伴，需要在企劃中確定理由；數量、來源、適用條件與取得難度目前待定。

### 俯視槍戰的設計要求【方向已確認，具體方案待定】

參考遊戲：[《逃離鴨科夫》官方Steam商店頁](https://store.steampowered.com/app/3167020/Escape_From_Duckov/)。此處記錄使用者指定的俯視槍械角度；官方介紹亦包含資源搜集、武器與撤離循環。精確鏡頭與我們的實作方式仍須另定。

已確認採固定朝向並跟隨主角移動。使用者進一步確認要有《逃離鴨科夫》類型的鍵鼠操作感、360°自由瞄準，以及整個人物連續平滑轉身的視覺感覺。鏡頭觀看方向固定與人物自由轉身可同時成立。俯視傾斜角度與取景範圍留待原型調整。

操作提案：WASD 控制相對畫面的移動，滑鼠位置決定水平360°瞄準方向，左鍵射擊；能向左移動同時向右射擊。具體按鍵、轉向反應、後座力與準星表現透過原型調整，不宣稱已重現參考作品的完整手感。

參考補充：2025年10月的[原版玩家一手討論](https://steamcommunity.com/app/3167020/discussions/0/598540711282197294/?l=turkish)區分了俯視傾斜角度切換與尚希望加入的自由旋轉；[相機旋轉模組作者說明](https://steamcommunity.com/sharedfiles/filedetails/?id=3591182470)則介紹額外旋轉控制。這些是參考資料，並非最新官方完整按鍵表。

優先驗證以下提案：

1. 鍵鼠操作中移動與瞄準方向分開；人物可連續轉身，射擊角度不鎖定在4或8個方向。手把支援後續再定。
2. 在固定朝向的跟隨鏡頭下，驗證俯視角度、取景距離與瞄準時的畫面偏移需求。
3. 玩家能看清瞄準方向、槍口位置與實際被障礙物阻擋的位置。
4. 房屋、牆面、樹木遮住角色時有清楚的視覺處理；讓角色可見與讓子彈穿透物件是不同規則。
5. 夥伴能通過門口與狹窄通道，避免長期擋住玩家移動與射擊；友軍碰撞、友軍傷害另定。
6. 原型先驗證同一地面上的戰鬥，再決定是否引入高低差。

畫面仍保留2.5D像素風目標。基於「整個人物也平滑轉身」，目前製作建議改為3D角色與場景、固定傾斜鏡頭，再以像素材質及低解析度呈現建立畫風。3D場景搭配4／8方向角色圖仍會有方向切換，故不作為此次轉身需求的首選。這是待原型驗證的技術提案；造型、光影與像素規格尚未定稿。

### 子彈時間

目的：給玩家更多現實時間觀察威脅、瞄準、選擇行進方向及撤退，支援混合型戰鬥。

已確認：採有限度使用，不能持續一直開啟；再次使用不需等固定冷卻完整結束。

以下為實現上述需求的提案，尚未確認：

- 建議以手動按鍵切換為初版方向；可提供按住啟動的操作選項。另一可選方式是瞄準時自動啟動。
- 使用一條有上限、可以分段消耗的能量槽。開啟時持續消耗，關閉後逐步回復；仍有足夠能量即可再次啟動，不必等到回滿。
- 能量耗盡時自動恢復正常速度；回復至最低啟動量便能再次使用。最低啟動量及是否需要少量啟動成本，留待試玩決定。
- 能量僅在關閉子彈時間且遊戲持續進行時自然回復；暫停選單不累積回復。安全狀態的日程跳時可按已經過的遊戲時間結算恢復，戰鬥中不使用日程跳時。
- 建議主角、同伴、敵人、子彈及換彈等戰鬥動作同步放慢，保持原本的速度關係；游標、介面和輸入仍即時回應。
- 世界時間依縮慢後的遊戲時間前進。生產、消耗、村落發展與每月期限都按同一遊戲時間結算。
- 與安全狀態的日程快轉分開：子彈時間延長玩家反應的現實時間；日程快轉用於略過已安排的日常過程。兩者建議互斥。
- 能量上限、消耗及回復速度、減速倍率，需要試玩後調整；目前不先設定數值。

### 核心循環【整合提案】

安全處整備 → 決定目的地與同行夥伴 → 親自選路步行 → 探索、搜集與戰鬥 → 判斷繼續深入或撤離 → 返回原據點或抵達下一處落腳點 → 使用物資改善裝備、生活或村落關係 → 決定下一次行動。

同一套冒險玩法服務不同身分：自由人為旅程取得補給，居民履行貢獻，想成為領導者的人協助社群發展。各項收益與身分之間的具體規則仍屬提案。

### 尚未決定

- 精確俯視角度、取景距離、操作方式、混合戰鬥的具體速度、近戰與遠程比例。
- 子彈時間的啟動方式、減速範圍、能量等限制的具體實現與時間結算規則。
- 探索區域如何產生，以及混合補充原則下各類資源與敵人的刷新、重訪規則。
- 連續世界中的撤離完成條件、營地與修復房屋的具體功能、存放物資的規則。
- 同行人數、夥伴自主行為與可下達的簡單指令。
- 背包限制、個人財物與公共資源的邊界。
- 工藝解鎖途徑、製作參與方式、配方、裝備成長、工坊條件與修理成本。
- 輕度求生的需求種類、消耗速度、自動處理方式與極端不足後果。
- 主角倒下後由誰救援、在哪裡恢復。
- 夥伴倒地條件、救援流程、救援時限、永久失去的判定與重要人物撤離規則。

## 6. 日程與跳時【規則提案，未確認】

1. 可在安全條件下，為角色安排休息、製作、修理等活動，推進至完成時間或指定時間。
2. 開始前顯示預計耗時、物資消耗，以及期間到期的事項。
3. 同一名角色同一時間只能參與一項互斥工作。
4. 跳時期間，角色活動、資源消耗、村落發展及貢獻期限經過同一段時間。
5. 遇到危險、資源不足或需要玩家決定的故事事件時，停止跳時並交還操作。
6. 未知區域探索、搜刮與正在進行的戰鬥，先以玩家親自操作為原則；哪些熟悉的活動可納入日程，之後再定。

製作提案：村落可先以定期結算資源和建設進度的方式發展，再以場景中的工作及建築變化呈現。更新頻率、模擬細節與效能需要原型驗證。

## 8. 主線故事與開場流程

### 完整遊戲的故事形式【已確認】

- 有明確主線結局，逐步回答藥劑、神秘NPC等疑問。
- 玩家自行決定何時推進主線。
- 結局之後仍能繼續自由生活、探索及參與村落發展。
- 第一個可玩版本優先完成主角、AI與神秘NPC的相遇、互救及同行，也就是三人逃難序章。

完整主線的真相、章節、結局內容及達成條件尚未撰定。序章可以有清楚的事件順序，以建立基本操作與角色關係；序章之後的自由生活與主線推進方式再逐步展開。製作提案是讓主線進度與是否擔任村落領導者分開，保留不同生活路線。

### 已確認的時間銜接

在危機爆發一天後開始。主角先在家分配現有的有限物資，為撤離做準備，再決定何時離開。

具體的居家事件、準備次數、能攜帶多少物品，以及什麼情況促使離家，尚未決定。

## 9. 第一個可玩版本：三人逃難序章

### 已確認的優先目標

優先完成主角、AI與陌生NPC的相遇、互救及同行。首版的核心評估是玩家能否感受到熟悉生活的崩潰、三人的關係，以及共同逃生的合作感。

### 建議範圍與收尾【提案】

一處住所、一小段相連的街區及通道、一個臨時安全點；玩家全程親自走動。經有限準備、首次遇敵、兩次互救與藥劑事件後，三人抵達暫時安全處並決定同行，作為首版收尾。

具體場景、給藥時點、對話與人物背景仍是創作提案。完整搜打撤與修屋循環、村落自主模擬、完整工藝及主線結局屬後續完整遊戲的內容，不列為序章完成條件。

### 製作順序建議

| 階段 | 可檢查的成果 |
| --- | --- |
| 操作基礎 | 用暫用素材完成主角移動、固定跟隨鏡頭、瞄準射擊、遮擋與有限子彈時間。 |
| 可步行的序章路線 | 住所、街區及終點在空間上相連；玩家可以自行走完。 |
| 三人事件與合作 | AI的日常互動、陌生人的出現、雙向救援、異常資訊及藥劑情節形成順序。 |
| 完整收尾 | 角色決定同行，序章有明確結束狀態；重試與進度保留方式可用。 |
| 表現與修整 | 依操作原型確定素材規格，再完善像素美術、音效、對話節奏與介面。 |

每個階段以可操作、可檢查的小成果推進，不先承諾完成日期。

### 序章驗收提案

1. 玩家理解開場是爆發一天後，能在家中有限資源之間作出取捨，並看見至少一項準備的用途。
2. 玩家只操作主角，以固定朝向跟隨鏡頭親自走過住所、街區及終點。
3. 基本槍戰與合作撤退可完成；子彈時間有使用限制，也能在未完全恢復時再次使用。
4. 雙向救援均透過可理解的事件成立，讓三人決定同行有依據。
5. 玩家感受到主角與AI的既有熟悉關係，也看見陌生NPC的異常資訊與藥劑；AI能力保持已確認設定。
6. 玩家能抵達暫時安全處並完成序章；事件不會因重試而重複授予獨有物品或卡住進度。

### 序章完成後的擴充提案

先接入一處可修復住處與一次外出收集、返程、工藝改善的完整循環，再引入日程、村落自主發展、貢獻與身分路線。此後逐步延伸完整製造、更多夥伴與主線章節。優先順序可以依序章試玩結果調整。

## 10. 待定事項與試作決策

### 進入操作原型前先處理

1. 以家中Windows電腦及已確認的鍵鼠操作為測試起點；具體按鍵仍是提案。優先用3D暫用操作場驗證360°瞄準與人物平滑轉身，再定正式渲染與美術規格。
2. 核對已安裝的 Godot 版本、專案位置、素材取得方式與可用驗證工具。
3. 依資源準備計畫製作最小暫用操作場；角色背景和正式劇情不是此階段的前置條件。

### 劇情細節稍後處理

1. 給三名角色建立簡短人物卡；名稱與外觀在初期可先用暫稱與暫用素材。
2. 選定兩次互救的具體事件、藥劑施用時點，以及抗體與不可逆感染的邊界。
3. 決定序章中的失敗重試、重要人物提前撤離及重逢如何銜接，避免事件無法繼續。功能測試可先用暫用事件與重試點；敘事驗收在劇情定稿後進行。

### 用原型調整

鏡頭角度、角色與槍械尺寸、遮擋表現、移動與瞄準手感、夥伴跟隨、子彈時間消耗及回復、補給量與教學節奏。這些不需要在方向初稿中先填滿數值。

### 完整遊戲後續設計

- 主角及兩名早期夥伴的性格、外觀與個人目標。
- 災前其他科技的程度、仿人型AI的社會地位，以及主角如何取得自己的AI。
- 主角原本的職業與能力，以及陌生NPC資訊的來源與範圍。
- 主角抗體的保護範圍、藥劑施用時點與無法普遍供應的原因。
- 重要劇情人物主動撤離的觸發、代價與保護範圍。
- 喪屍行為、感染方式、是否攻擊仿人型AI，以及末日故事的調性。
- 日程中斷、月度貢獻、加入與離開村落的具體規則。
- 技術取得方式、工坊使用條件、工作分配與完整製造的成長節奏。
- 營地功能、房屋修復與使用權、倉庫是否互通，以及住處的安全程度。
- 自然資源、商隊、廢墟物資與敵人的具體補充或重返規則。
- 同行隊伍人數、夥伴的自主行為與簡單指令。
- 自主村落的成長與衝突，是否可能導致衰退或毀滅。
- 鏡頭與瞄準手感、失敗代價、救援流程、夥伴風險與AI受傷恢復方式。
- 完整遊戲的存檔、遊戲時長、章節與結局內容；序章完成條件以第9節提案為起點。

## 11. 方向決策紀錄

- 彙整此前對玩法、身分路線、世界自主性、日程及隊伍的共識。
- 將開場時間記為危機爆發一天後。
- 確認有限準備發生在爆發一天後、撤離前，在家分配現有物資並決定何時離開。
- 確認主角獨居，AI災前已相識，平常提供家務、飲食與日常安排等生活照料。
- 確認第三位角色知道不尋常資訊、能預判部分危險但說得保留，經互救後才決定同行。
- 確認仿人型AI災前已商品化但昂貴，只有少數家庭或機構擁有。
- 確認開局AI戰鬥能力與主角基本相同，沒有改造；優勢是免疫感染與身體較硬朗。
- 確認感染不可逆，主角由神秘NPC提供的不知名藥劑取得抗體。
- 確認夥伴救援失敗會永久失去，重要劇情人物在死亡前先逃離；具體判定仍待定。
- 確認參考《逃離鴨科夫》的俯視槍械角度；提出先以射擊、瞄準與遮擋原型驗證視角的製作順序建議。
- 確認戰鬥結合事前準備與即時走位、瞄準，加入子彈時間降低操作門檻。
- 確認鏡頭觀看方向固定，跟隨角色移動。
- 確認鍵鼠操作、360°自由瞄準，以及整個人物連續平滑轉身；更新原型為優先驗證3D角色與場景搭配像素風呈現的提案。
- 確認子彈時間採有限度使用，不能一直開啟，但無須等待完整冷卻才能再用；提出可分段消耗、關閉後逐步回復的能量槽方案。
- 確認採連續步行世界，玩家親自走過相連地點；提出從小範圍相連場景逐步擴展的製作建議。

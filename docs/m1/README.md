# M1 操作樣板：交付紀錄（Three.js 版）

更新日期：2026-10-12

這份紀錄對照 [`docs/design/goal-start-brief.md`](../design/goal-start-brief.md) 的 M1 完成條件。它分開列出三類結果：自動化實際執行過的檢查、以程式模擬滑鼠鍵盤完成的互動測試，以及還需要真人試玩才能確認的項目。

## 1. 環境與版本

| 項目 | 版本或設定 |
| --- | --- |
| 渲染函式庫 | Three.js 0.186.1（WebGL 2） |
| 建置工具 | Vite 8.3.4、TypeScript 5.9.3、Node.js 22 |
| 單元測試 | Vitest |
| 瀏覽器測試 | Playwright 1.56.1，Chromium 無頭模式，SwiftShader 軟體 WebGL，視窗 960×540 |
| 測試環境 | 雲端 Linux 容器，沒有顯示卡 |

軟體 WebGL 在測試中只有每秒 10～25 幀，實機顯示卡會快很多。測試依「遊戲內時間」與狀態變化判斷，不依賴幀率。

最近一次執行：單元測試 25 項全數通過；瀏覽器驗收 16 項全數通過（含外部角色模型的載入與動作測試）。

## 3. 尚未驗證，需要真人試玩

- 實際手感：轉身速度、移動加速度、後退減速、射速與散布。
- 鏡頭：俯角、取景距離、瞄準時的畫面偏移量是否舒服。這些都能在暫停選單即時調整。
- 實機效能：家中 RTX 4090 上的幀率（預期穩定 60 幀以上，但沒有實測）。
- Windows 的字型顯示與系統縮放：繁體中文字型由 Google Fonts 載入，離線時會改用系統字型。
- 音效聽感：音效以程式即時合成，只確認過程式能執行，沒有人實際聽過。
- 長時間遊玩後的穩定性，以及不同螢幕比例下的版面。

## 6. 外部角色模型

主角與喪屍已換成 Quaternius 的低多邊形模型（Adventurer、Animated Zombie，CC0），做法見 [`src/assets/models/README.md`](../../src/assets/models/README.md)。移除模型檔時會退回方塊暫用人形。

| 項目 | 主角（Adventurer） | 喪屍（Animated Zombie） |
| --- | --- | --- |
| 使用的動作 | 持槍待機（下半身）、持槍瞄準（上半身）、前後左右跑步、死亡 | 待機、跑步、撲咬（截取 0.2～1.5 秒） |
| 量到的設計速度 | 跑步 3.03 m/s、走路 1.34 m/s | 跑步 3.33 m/s、拖步 0.41 m/s |
| 遊戲中的播放 | 主角約 4.6 m/s，跑步動作約 1.5 倍速 | 喪屍約 2 m/s，跑步動作約 0.6 倍速 |
| 槍口 | 依瞄準姿勢量出右手位置：右側 0.19 m、離地 1.37 m、前方 0.61 m | — |
| 缺少的動作 | — | 死亡（改用程式倒地）、後退 |

| 項目 | 做法 |
| --- | --- |
| 檔案 | `src/assets/models/player.glb`、`zombie.glb`（也接受 `.gltf`、`.fbx`） |
| 尺寸 | 依綁定姿勢量出高度，等比縮放到 1.8 公尺，腳底貼地、置中 |
| 動作辨識 | 依名稱找出待機、走、跑、後退、死亡、攻擊、受擊；持槍版本與喪屍專用動作優先 |
| 移動動作 | 依實際速度切換並調整播放速度；沒有後退動作時把前進動作倒著播 |
| 橫移與後退 | 有前後左右跑步動作時依方向混合並同步步伐；只有前進動作時，髖部轉向移動方向、脊椎反向轉回。上半身與槍都維持對準滑鼠 |
| 槍 | 外部模型通常不附槍。有瞄準姿勢時改用暫用手槍並放在右手上，槍口位置依姿勢量測，子彈、雷射與畫面上的槍一致；沒有瞄準姿勢時沿用暫用步槍 |
| 剪影與閃色 | 被牆擋住時的剪影、受擊閃色都套用到外部模型 |
| 找不到模型或載入失敗 | 自動退回方塊人形，主控台留下警告，遊戲照常運作 |

驗證方式：以 three.js 範例附的 RobotExpressive 模型（作者 Tomás Laulhé／Quaternius，CC0）暫時放入資料夾測試，確認待機、跑步、橫移、後退、喪屍追擊與攻擊、倒地動作都能播放，單一 HTML 版本也能載入內嵌的模型。這個測試模型沒有放進儲存庫。

## 7. 這版的畫面做法（給比較 Godot 版時參考）

- **像素風**：場景先畫到低解析度畫面，再以最近鄰放大。介面另外用 HTML 繪製，不會被像素化。
- **像素描邊**：依深度與法線的變化，在物件外緣畫深色線，稜線則提亮。
- **鏡頭不閃爍**：鏡頭位置先對齊像素格再渲染，合成時補回不到一格的位移。這樣鏡頭平滑跟隨時，畫面不會出現像素爬行。
- **遮擋處理**：擋在鏡頭與角色之間的高物件以像素網點淡出；仍被擋住的部分顯示半透明剪影，主角為藍色、喪屍為紅色。
- **光影**：卡通式三段明暗、月光陰影、槍上的手電筒光錐（含陰影）、路燈、火桶閃爍光、開槍閃光。
- **子彈時間**：畫面降飽和偏冷色、啟動波紋、音效低通與降調；子彈與粒子一起放慢。

## 8. 已知限制

- 喪屍只會直線追擊和格子尋路，沒有視野與聽覺判定。
- 牆面淡出只看主角的位置，不看喪屍。
- 方塊暫用人形的動作是程序擺動；放入外部模型後才有骨架動畫。
- 測試場是單一場景，沒有分區載入。

## 9. 下一步建議

1. 你在家中電腦試玩，記下手感上不舒服的地方。暫停選單可以直接調整俯角、取景、瞄準偏移、像素大小與子彈時間的啟動方式。
2. 和 Godot 版比較以下幾點：畫面表現、調整手感的方便程度，以及接下來 M2（相連路線）與 M3（三人事件）的製作負擔。
3. 決定引擎後，再進入 M2：住所、街區、替代通道與臨時安全處的相連路線。

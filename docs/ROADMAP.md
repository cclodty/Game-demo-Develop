# 子彈芭蕾 Bullet Ballet — 規劃書第四版：第二代（Steam、Godot 4、二次元）

2026-10-16 初版 · 2026-10-22 第二版 · 2026-10-26 第三版 · **2026-10-27 第四版**：開發者試玩彈幕 ② 之後，與 Claude 一輪問答定了重玩動機、平台、引擎、畫風、世界觀、玩家、敵人、一局與局外。第三版原文在 `docs/ROADMAP-2026-10-26.md`（彈幕、人盾、骨架、頭目、主題房的玩法規格；這一版引用它，不重抄），第二版在 `docs/ROADMAP-2026-10-22.md`（TASKS.md、DECISIONS.md 引用的 §編號指向它）。這一版是現行的；第二代的細節在 `docs/REDESIGN.md`。

## 1. 摘要

**開發者 2026-10-27 的結論：** 自己覺得好玩的地方有了（子彈時間、花俏的動作、多工具用法、房間互動），但**缺重玩的動機**：不像倖存者類，深化和研究的地方不多，變化不大；作為網頁遊戲改改美術或許過得了關，但也僅此而已。另外，模型、美術和部份基底都是重做前的，想在沒有局限的情況重看一次，先寫好規劃書。往後不想單純是網頁遊戲，複雜一點的美術也接受，可以花錢用 Meshy 做模型。

**十四個決定（DECISIONS 2026-10-27）：**

| 題目 | 決定 |
|---|---|
| 重玩動機 | 這是**技巧型**遊戲，不追倖存者類的「數字一直升」。深化靠 ① **精通可以研究**（花招手冊、每房評級、看得明的風格計分）和 ② **風格卡擴成 build**；另加 ③ 每個出口兩道門的路線選擇、④ 敵人詞綴、⑤ 房內自選挑戰、⑥ 通關階梯。排行榜與每日挑戰**暫不討論**（只有一個玩家） |
| 加難度的獎勵 | 分數不是獎勵。獎勵四類：**局內力量**（多一張卡、稀有卡、專注上限、特別武器、一條命）、**局外新內容**（卡池、房、武器、變體的解鎖全部掛在挑戰和階梯上）、**表達**（殘影顏色、擊殺鏡頭濾鏡、音樂層、最佳一幕）、**一條線索**（頭目掉「檔案」頁，拼出一夜的故事） |
| 平台 | **Steam 桌面版**；線上試玩是必須的 |
| 引擎 | **Godot 4，GDScript（靜態型別），Compatibility 渲染器**。C# 至今不能輸出 Web；Web 版要 SharedArrayBuffer 的兩個標頭（itch 有開關，GitHub Pages 用 coi-serviceworker）；Compatibility 才出得了 Web，Steam 版用同一套 |
| 次序 | **先在 JS 原型收尾設計，再搬**。原型快、有測試、數字即時試得到；美術和 Meshy 的錢全部落在新引擎，JS 版不再做模型 |
| 畫風 | **二次元，都市潮流動畫的口味**（絕區零、女神異聞錄）：鮮色、街頭時裝、漫畫分格轉場、斜切 UI。俯視鏡頭看不到面，二次元最難的部份被鏡頭避開；味道由角色的色塊與剪影、賽璐璐描邊、特效與鏡頭、UI 來 |
| 世界觀 | **架空都市，帶港澳味**。城市名、幫派身份、「一夜」的時間線要新寫；主題房的身份（茶樓、大排檔、廣場、跑道彎、石階、直街、碼頭、天台、夜店）是港澳通用的場景，照用，不再是真實地點 |
| 玩家 | **槍手特技演員（現狀深化）**。新特技：**牆跑與扒牆**、**環境特技**（每間主題房一種）；武器**多而靠手感**（手感靠後座、鏡頭震、射速、聲、子彈的樣子，不靠模型） |
| 敵人 | 重設計：**每種敵人一個題目**（他出的彈幕題目 × 做人盾時的效果 × 克制哪個特技），十至十二種；職業和外形跟題目走 |
| 頭目 | **四至六個人類頭目，每層抽**；各加一個階段和幫派身份；最終頭目固定 |
| 一局 | **三層、十分鐘，講口工**（機械人現在 16 分鐘，要壓下來） |
| 局外 | **一個小基地**：揀裝備和外觀、看花招手冊和檔案、試槍場、解鎖變體 |
| 音樂 | **真音樂，外判或 AI 生成**：每層一首、頭目一首、基地一首；子彈時間的慢放用時間伸展 |
| 資產 | **Meshy 生成，照用不修（先試）**：一張設定圖、固定的 prompt 模板、自動 rig、Mixamo 動畫，賽璐璐後處理統一；不對就重生 |
| 鏡頭與操控 | **不變**：固定俯視、幾個視角、滑鼠瞄準、手掣、觸控 |

**定位一句話：** 用子彈時間在滿屏快彈之間跳舞；工具、人盾、房間都是解法。一個架空的港澳夜都市，二次元畫法。

**完工的定義（改寫）：** 三個階段各有自己的完工：JS 原型「設計收尾」（§7 附錄）；Godot 版打得出同一局（§7 G 組）；美術、音樂、基地做完上 Steam（§7 H 組、I）。

## 2. 支柱

1. **打得漂亮比打得多重要。** 分數、評級、解鎖都獎勵花式和多樣性。
2. **子彈時間是解題工具，不是無敵按鈕。**
3. **彈幕是題目，一定有缺口；工具、人盾、房間互動都是解法。**
4. **一局十分鐘，每一局都留低東西，而且下一局有新東西玩。**（改寫：解鎖是獎勵的核心；一局結束帶走評級、片段、一步解鎖，下一局多一張卡、一間房、一支槍或一個變體。）

**三條線**不變：打得精彩、地圖會說話、不開槍也能打。

**港澳味**是美術方向，不是支柱，也不再是真實地點：房間是港澳常見的場所，城市是架空的；不用真實店名、品牌、人物、事件。

## 3. 重玩動機與獎勵

技巧型遊戲的重玩來自三處，不來自道具數字：

| 來源 | 做法 | 卡 |
|---|---|---|
| **精通可以研究** | **花招手冊**：每種互動一個條目，首次做到就點亮，未發現的只顯示提示；**每房評級** S／A／B 按「用了幾多種不同花招」計，不按殺幾多人；**風格計分看得明**：每個花招彈出名字和倍率 | F⑤ |
| **build** | 風格卡擴到 18–24 張，每張仍是一個開關；加標籤（滑鏟、人盾、慢鏡、反彈）、兩三張組合卡（持有兩張同標籤才生效）、代價卡（沒有慢鏡但 Style 雙倍、只得手槍但慢鏡無限）；揀卡時顯示配合 | F④ |
| **揀路** | 每個出口兩道門，門上標下一間房和獎勵（「廣場・一支散彈槍」／「後巷・一張卡・精英」） | F③ |

再加三樣令每局不同：**敵人詞綴**（鐵頭不能抓、彈衣死時爆、快槍、盲射沒有紅線、黐身；第二層起每房抽一兩個，F①）、**房內自選挑戰**（不開槍／不用慢鏡／無傷／限時，做到加 Style 和一個局內獎勵，F②）、**通關階梯**（通關解鎖第 1 級，每級一個固定修飾，到第 10 級，F⑥）。

**獎勵四類**（加難度換什麼）：

| 類 | 例 |
|---|---|
| 局內力量 | 四選一、一張稀有卡、專注上限多一格、一支特別武器、一條命 |
| 局外新內容 | 卡池初始八張，其餘由挑戰解鎖；主題房的夜晚版本要過日間版的挑戰；新武器要在某間房做到某個花招才入武器墊；變體掛在階梯 |
| 表達 | 外套顏色（已有）、殘影顏色、擊殺鏡頭濾鏡、音樂多一層、結算畫面「本局最佳一幕」有名字 |
| 一條線索 | 每個頭目在高一級打低就掉一頁「檔案」，十幾頁拼出一夜的故事 |

排行榜與每日挑戰的程式留下（`legacy`），有試玩者才回來。

## 4. 玩法規格（引用第三版）

彈幕的規格（第三版 §4）、人盾資源（§5）、風格卡第一批（§8）不變。一局的骨架（§6）加：兩道門、自選挑戰、階梯、基地（§3）。三層十分鐘不變：機械人現在 16 分鐘，F⑦ 用量度工具一層一行壓到 ≤ 12 分鐘（目標 10）。

## 5. 主題房

| 房 | 獨特互動（= 環境特技） | 狀態 |
|---|---|---|
| 茶樓（連廂房、偏廳） | 翻枱做牆、點心車踢出去撞人 | 做完 |
| 大排檔 | 石油氣罐踢出去噴射 | 做完 |
| 廣場 | 白鴿群驚起擋視線、噴水池落水 | E① 做完 |
| 跑道彎 | 賽車定時掠過，是會殺人的移動牆；紅燈預警 | E② 做完 |

| 直街 | 鐵閘封路、踢門穿屋 | E④ 做完 |
| 碼頭 | 水邊踢人落海、手推車 | E⑤ 做完 |

## 6. 玩家、敵人、頭目

**玩家是槍手特技演員。** 現有五樣（滑鏟、旋轉、踢、抱、雙槍分瞄）加飛撲、處決、擲物保留；新加**牆跑與扒牆**（沿牆走一段、由牆踢出；房要有內牆，F⑨）和**環境特技**（每間主題房一種，§5）。武器**多而靠手感**：初版十二支，每支的射速、後座、彈匣、聲、子彈的樣子各異（`docs/REDESIGN.md` §4）；撿槍是揀火力，不是揀解法。

**敵人每種一個題目。** 十至十二種，每種三欄：他出的彈幕題目、做人盾時的效果、克制哪個特技；職業和外形跟題目走（§REDESIGN 5）。JS 原型先做行為（F⑧），外形留給 Godot。

**頭目四至六個人類**，每層抽一個；各加一個階段和幫派身份；最終頭目固定（第三層）。載具類不上場。

## 7. 第二代：平台、引擎、美術

三個階段，各有完工定義；**只有 JS 原型階段在這個倉**。

| 階段 | 做什麼 | 完工 |
|---|---|---|
| **JS 原型收尾**（E、F 組） | 主題房做完、深化六張卡做完、一局壓到 ≤ 12 分鐘、開發者試玩一輪出 Markdown 回饋 | 設計定了：規則、數字、房、敵人行為、卡、獎勵表全部是資料，可照 `assets/SPEC.md` §8 輸出 |
| **Godot 搬遷**（G 組） | Godot 4、GDScript 靜態型別、Compatibility；固定 120 Hz 步進、種子 RNG、輸入記錄與重播、測試與機械人、Web 輸出 | Godot 版用積木人打得出同一局（機械人數字對得上 JS 版）；Web 版在 itch 玩得到 |

Godot 的工程規劃、資產清單第二版、美術聖經、世界觀在 `docs/REDESIGN.md`。JS 倉之後是原型與設計資料的來源；搬遷後新倉（或 `godot/` 目錄，到 G① 才定）。

## 9. 風險與對策

| 風險 | 後果 | 對策 |
|---|---|---|
| 換引擎是重寫 | 幾個月沒有新玩法 | 設計在 JS 定好才搬；G 組每步用機械人數字對 JS 版；積木人先搬，美術後上 |
| Meshy 一致性 | 不同次生成的角色風格不一 | 一張設定圖、一個 prompt 模板、賽璐璐後處理統一；H① 先試產三個再決定 |
| GDScript 的效能 | 幾百粒子彈每秒 120 步 | 靜態型別、MultiMesh 繪製；門檻 500 粒不跌幀；不夠才把子彈步進落 GDExtension |
| Web 版的上游問題 | macOS／iOS 的 SharedArrayBuffer 與 WebGL 2 | G⑦ 先在開發者的機器驗證；不行就只做下載試玩 |
| 一個人、沒有試玩者 | 數字只有開發者一個人判斷 | 照舊：數據面板、回饋匯出、每張卡附數字 |
| 三層十分鐘壓不下來 | 一局太長，重玩動機下降 | F⑦ 量度一層一行；房數、波數、人數都是資料 |
| 範圍 | 三組二十多張卡加一次搬遷 | 一張卡一天、「這次不做」；G 組每步有「同一局打得出」的驗收 |

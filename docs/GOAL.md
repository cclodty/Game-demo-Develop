## 技術上要守的
- 遊戲邏輯只用 game.rng，不用 Math.random；特效用 utils.js 的 rand。邏輯在 120 Hz 固定步裡運行（main.js 的 step/logic），新系統放進 logic，不放 present。一局留下的東西（倒下的招牌、落下的鐵閘、熄滅的街燈、重排的道具）要在 resetWorld／resetProps 重設（test/seed.test.mjs 會抓）。
- 輸入只從每步的 game.cmd（StepInput）讀。新動作盡量重用現有鍵（F、G、左鍵）；真的要新鍵就加在 input.js BUTTONS 的最後，記錄格式版本號跟着升，重播測試要過。
- 互動件、門、水邊、工具都是地圖資料（maps.js 的 fixtures／doors／water／tools／stages／perches），行為寫在系統（fixtures.js、level.js、enemies.js）。不寫「只有這張地圖才有」的程式；一張地圖獨有的東西也要用資料表達。
- 掩體改變時（門開關、鐵閘落下、招牌落地、木箱碎）要 nav.buildRect 局部重建並讓 hasLOS／raycast 看到；敵人的路徑會自己重算（repath）。
- 敵人的新狀態放進現有狀態機（enter／move／aim／fire／recover／chase／…），沿用 requestToken、blind、kick、stun 等現有機制；黑暗、煙霧、網都用 blind／stun 表達，不另建一套。
- 擊殺標籤在 main.js onEnemyKilled 一處決定；新標籤的分值先用卡上的第一版，記 DECISIONS。
- 風格層 src/style.js 只管渲染。新加進場景的東西要過 game.style.dress()；新的人物姿勢經 characters.js KEY_POSES 與 style.poseDue()。?style=off 必須玩起來完全一樣。
- 每張地圖有渲染預算（maps.js budget）。超出就減東西，不要調高預算；新地圖量度後寫入自己的預算。
- 不加執行期依賴；不碰 senado/；不換引擎；repo 裡不放密鑰與個人資料。福隆新街的店名、招牌、人名全部虛構。

## 寫測試要避開的坑（前兩階段 CI 紅過的原因）
- 不要斷言取決於隨機冷卻的時間點。用固定種子（?seed=）並逐格檢查狀態。
- 擺位後先把被擺位過程影響的狀態重設，再開始量度（敵人用 e.update = () => {} 定住；殺戮鏡頭與停格會改時間倍率，量子彈飛行前先清掉 killcamT、hitstopT、焦點）。
- 敵人生成後有一段 spawnLock，期間子彈穿過；測試先等它過去或設為 0。
- 開兩個頁面的測試，先停掉第一個頁面的畫面循環（g.frame = () => {}）；頁面在 try/finally 裡關閉。
- 不要用 Date.now 或系統時鐘決定測試結果；每日挑戰的測試要能注入日期。
- 地圖驗證器（test/maps.test.mjs）會對每張地圖跑；改地圖資料後先本機跑它。
- 未完成的測試草稿不要放進 test/。

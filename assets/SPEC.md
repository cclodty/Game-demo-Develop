# 比例尺寸與交付規格

這份文件是做 3D 模型時的「尺」：遊戲裡每樣東西有多大、模型要怎樣交付，以及日後轉用其他遊戲引擎要預先注意什麼。

- 每一件物件的提示詞：[PROMPTS.md](PROMPTS.md)
- 機器可讀的清單：[asset-list.json](asset-list.json)（也有 [asset-list.csv](asset-list.csv)，可用 Excel 開）
- 四張地圖的佈局：[maps/](maps/)
- 處理和放進遊戲的流程：[README.md](README.md)

以上清單和地圖檔都由 `npm run assets:docs` 從程式自動生成，所以數字和遊戲永遠一致。

---

## 1. 單位與座標

| 項目 | 規定 |
|---|---|
| 單位 | **1 單位 = 1 米**，一律按真實大小建模 |
| 上方向 | **+Y** |
| 模型正面 | **+Z**（人物的臉、道具的正面、槍口都向 +Z） |
| 座標系 | 右手座標，即 glTF 2.0 的標準 |
| 遊戲世界 | x 向東（畫面右），z 向南（向著預設鏡頭），原點在可玩範圍中心 |

**模型原點（pivot）放在哪裡：**

| 類別 | 原點 |
|---|---|
| 人物 | 兩腳之間的地面 |
| 道具、環境物 | 底部中心（貼地） |
| 武器 | 主手的握把位置，槍口或刀尖指向 +Z |
| 建築 | 佔地中心、地面高度，正立面向 +Z |

## 2. 鏡頭與畫面上的大小

| 項目 | 數值 |
|---|---|
| 預設鏡頭 | 45° 側俯視（按 V 可切換俯視、45° 俯視） |
| 鏡頭距離 | 22.7 米；議事亭前地 31 米 |
| 視角（FOV） | 40°；議事亭前地 30° |
| 子彈時間 | 鏡頭拉近約 14% |
| 1080p 畫面上的人物 | 約 **90–110 像素高** |

**對建模的意思：**
- 在現在的鏡頭下，看得到的是**輪廓和大色塊**。臉部、縫線這類細節看不見，但會保留在高質量母版裡，日後換引擎或用近鏡頭時就用得著。
- 每個陣營要有一個**主色**，遠看也分得出敵我（見下面人物表）。
- 會爆的東西（油桶、氣罐、石油氣罐）要一眼看得出危險：鮮紅、鮮橙、警告標誌。

## 3. 人物

遊戲的人物比例以真人為準，和議事亭前地模型裡的比例人一致。

| 部位 | 尺寸（米） |
|---|---|
| 身高（頭頂） | **1.78** |
| 肩寬 | 約 0.46（兩邊肩關節相距 0.54） |
| 腿長（地面到髖） | 0.90 |
| 軀幹 | 0.44 寬 × 0.24 厚 × 0.56 高，中心離地 1.18 |
| 頭 | 0.20 寬 × 0.23 高，中心離地 1.60 |
| 手臂 | 肩高 1.40，臂長約 0.58 |
| 持槍高度 | **1.38**（子彈就在這個高度飛） |

| 角色 | id | 碰撞半徑 | 遊戲裡的身高 | 主色 |
|---|---|---|---|---|
| 主角 | `hero` | 0.30 | 1.78 | 青綠 #2EE8FF |
| 打手 THUG | `grunt` | 0.32 | 1.78 | 紅 #FF2D4A |
| 散彈手 SHOTGUNNER | `shotgun` | 0.34 | 1.78 | 橙 #FF8A1F |
| 步槍手 RIFLEMAN | `rifle` | 0.32 | 1.78 | 紫 #B36BFF |
| 刀手 BLADE | `rusher` | 0.30 | 1.78 | 洋紅 #FF2BD0 |
| 大隻佬 BRUTE | `brute` | 0.48 | 約 2.2（照 1.78 米做，遊戲放大 1.25 倍） | 紅 #FF3A2A |

**人物的共同要求：**
- **姿勢**：A-pose（雙手向下約 45°），手上不拿武器（武器另做，遊戲會放到手上）。
- **同一套骨架**：全部人物共用一套人形骨架，用 Mixamo 式的骨頭名稱（`Hips`、`Spine`、`Spine1`、`Spine2`、`Neck`、`Head`、`LeftShoulder`、`LeftArm`、`LeftForeArm`、`LeftHand`、`LeftUpLeg`、`LeftLeg`、`LeftFoot`、`LeftToeBase`，右邊同樣）。
  - 動作可以在不同人物之間共用；Unity、Unreal、Godot 都能自動對應這套名稱。
- **動作**：原地播放（不帶位移），每個動作一個獨立、有名字的片段。
  - 必須：`idle`、`run`、`death`
  - 最好有：`walk`、`strafe_left`、`strafe_right`、`run_backward`、`kick`、`hit_react`、`dodge_roll`、`dive`、`climb_up`、`reload`、`melee_slash`
  - 現在的網頁版只用 idle、run、death：瞄準、側行、後退、踢和翻滾都由遊戲控制，雙手用 IK 自動握槍。其餘動作留給日後的版本或其他引擎。

**議事亭前地是按 OpenStreetMap 的實際比例建的：**
- 廣場口寬 37.9 米，廣場長 108.6 米，到玫瑰堂 144.6 米。
- 窄段路面寬 6.8 米，兩邊樓宇之間 10.3 米。
- 噴水池是一個直徑 14.2 米、向下三級（每級 0.16 米）的下沉圓形廣場。
  - 水池直徑 9 米、高 0.42 米；中間的盆直徑 5.8 米；渾天儀直徑約 1.7 米。
- 每棟樓的佔地輪廓和高度都在 [maps/senado.json](maps/senado.json) 裡。

**掩體的高度分三級：**

| 高度 | 例子 |
|---|---|
| 矮（0.8–1.3 米） | 木箱、路障、吧枱、熟食檔櫃枱 |
| 中（1.5–1.9 米） | 玻璃屏風、冷氣機、氣罐 |
| 高（2.2–3.4 米） | 喇叭、貨櫃、樓梯屋、霓虹柱 |

遊戲用平面判定，任何掩體都擋子彈，高度只影響外觀和視線。

**模型和碰撞是分開的：**
- 遊戲的碰撞用自己的盒子，數字在 `maps/*.json` 裡。
- 模型只需要外觀接近那個盒的大小，不用另做碰撞模型。

## 6. 高質量母版的技術要求

「母版」是交付的最高質量版本，永久保存。網頁遊戲用的版本由腳本自動減面、縮貼圖產生，日後換引擎就直接用母版。

| 類別 | 母版三角面 | 母版貼圖 | 網頁版（自動） |
|---|---|---|---|
| 主角 | 約 50,000 | 4096 | 10,000 面、1024 |
| 敵人 | 約 40,000 | 4096 | 6,000–8,000 面、1024 |
| 武器 | 約 12,000 | 2048 | 300–3,000 面、512 |
| 道具、環境物 | 約 8,000 | 2048 | 100–3,000 面、512–1024 |
| 地標建築 | 約 150,000（另附 1/4 的 LOD1） | 4096 | 12,000–20,000 面、2048 |
| 平鋪材質 | — | 2048 | — |

每一件的確實數字在 PROMPTS.md 和 asset-list.json 裡。

**檔案格式**
- **主檔**：GLB（glTF 2.0 二進位），貼圖嵌入在檔內。
- **人物、武器、白鴿**：另加一份 **FBX**。Unity 和 Unreal 對 FBX 的人形骨架支援最好。
- **貼圖**：另外存一份 PNG，方便日後在其他引擎重新組合材質。

**材質（PBR 金屬／粗糙度流程，glTF 標準）**

| 貼圖 | 檔名 | 說明 |
|---|---|---|
| 顏色 | `<id>_basecolor.png` | sRGB，**不可以烘焙光影**（遊戲要在夜景和日光下都用） |
| 法線 | `<id>_normal.png` | OpenGL 格式（綠色向上） |
| ORM | `<id>_orm.png` | 紅 = 環境遮蔽（AO）、綠 = 粗糙度、藍 = 金屬度 |
| 自發光 | `<id>_emissive.png` | 霓虹、燈、LED 等發光部分才需要 |

**網格**
- 乾淨的拓撲，不要有隱藏、浮空或互相穿插的多餘面。
- 縮放和旋轉要套用（scale = 1、沒有旋轉）。
- 一件物件盡量不超過 3 個材質。
- 人物在肩、肘、髖、膝要有足夠的線，彎曲時才不會變形。

**模組化物件**：牆身、矮牆、圍欄、路障、吧枱、沙發
- 照指定長度做一節，兩端要能無縫接駁。遊戲會按需要的長度重複排列，貼圖不會被拉長。

**命名**
- **id**：檔名一律用清單的 id，全小寫，用底線，例如 `weapon_shotgun.glb`。
- **版本**：同一件物件的不同版本用 `-` 分開，例如 `hero-v2.glb`。
- **分開的動作**：例如 `hero@run.glb`。

## 7. 交付資料夾

每件物件一個資料夾，放在 `assets/source/<id>/`：

```
assets/source/hero/
  hero.glb            主檔（貼圖嵌入；人物連骨架和全部動作）
  hero.fbx            人物、武器加交一份 FBX
  hero@dive.glb       （可選）分開存放的動作，只會取用裡面的動作
  textures/           分開的 PNG 貼圖
  reference/          用來生成的參考圖、設定圖
  NOTES.md            用了什麼工具、日期、方案或授權、修改紀錄
```

**大檔案**：GitHub 對超過 50 MB 的檔案會警告，超過 100 MB 會拒收。
- 母版太大時，先放雲端硬碟，在 `NOTES.md` 留下連結。
- 或者日後再為 `assets/source/` 開啟 Git LFS。

## 8. 轉用其他遊戲引擎的準備

**現在已經不依賴這個網頁引擎的部分：**
- **模型母版**：GLB、FBX 加 PNG，三大引擎都能直接匯入。
- **[asset-list.json](asset-list.json)**：每件物件的尺寸、原點、輔助點、動作清單和檔案位置。
- **[maps/*.json](maps/)**：四張地圖的掩體、玻璃、油桶、平底鑊、武器台、出生點、燈光、鏡頭；議事亭前地還有每棟樓的輪廓、噴水池和樹。
- **`senado/export/senado_massing.glb`**：議事亭前地專案匯出的整個街區模型。

**各引擎的分別**：匯入時要留意以下幾點，大部分匯入工具會自動處理。

| | 本專案（glTF） | Unity | Unreal Engine 5 | Godot 4 |
|---|---|---|---|---|
| 單位 | 米 | 米 | 厘米（匯入時自動 ×100） | 米 |
| 上方向 | +Y | +Y | +Z（匯入時自動轉換） | +Y |
| 模型正面 | +Z | +Z | 匯入後通常要轉向 | 引擎慣例是 −Z，模型要轉 180° 或在程式裡處理 |
| 法線貼圖 | OpenGL | OpenGL | DirectX：匯入時勾選「翻轉綠色通道」 | OpenGL |
| 匯入方式 | GLB | FBX；或 glTFast 套件讀 GLB | FBX；或內建的 glTF 匯入 | GLB（原生支援，最推薦） |
| 人物骨架 | Mixamo 名稱 | 設為 Humanoid，自動對應 | 用 IK Retargeter 對應到官方人偶 | 用 BoneMap（Humanoid 設定檔）對應 |

**仍然寫在程式裡的部分，換引擎時要重做：**
- **遊戲邏輯**：子彈時間、敵人 AI、武器手感。資料可以搬過去，但程式要按新引擎重寫。
- **地圖佈景**：霓虹字、舞池燈光節奏、遠景位置，目前寫在 `src/maps.js` 的 `decorate` 裡。等環境物的模型做好、放進遊戲時，會一併改成資料格式，匯出到 `maps/*.json`。

## 9. OSM 標籤 → 互動件（下一張 OSM 地圖用）

按 OpenStreetMap 建的地圖（議事亭前地；下一張可能是格蘭披治賽道一帶或大三巴），街上的東西可以由 OSM 的點位自動產出，不用逐件手放。這一節是對照表和流程。

**議事亭前地現在的情況**（2026-10-21 查過）：
- 遊戲用的 `src/senado/data.js` 只有樓宇、廣場、道路、噴水池和兩棵樹，沒有街道設施的點位。
- 子專案的 OSM 抽取 `senado/data/osm_street.json` 有 152 個節點，可玩範圍（52 × 148 米）內只有一支交通燈：
  - 巴士站 20、路樁 18、郵筒 2 全在範圍外
  - 這一帶的 OSM 沒有標街燈（`highway=street_lamp`），也沒有長椅
- 子專案的 `senado/data/streets.json` 有 `furniture`。這是 `build_streets.py` 按規則擺的，不是 OSM 點。可玩範圍內有：
  - 街燈 17 盞、雙頭街燈 2 盞
  - 長椅 4 張、垃圾桶 3 個、花盆 15 個
  - 交通燈 1 支、行人燈 1 支
- 所以議事亭那四盞射得熄的街燈仍是 `src/maps.js` 手放的。
- 要把子專案的街燈接過來，得改 `scripts/senado-extract.mjs`，再重新產生 `src/senado/data.js`。這件事已寫成待排卡（`docs/TASKS.md`）。

**對照表**（規則欄的數字是第一版建議）：

| OSM 標籤（括號是子專案 `furniture` 的名） | 遊戲裏 | 地圖資料 | 規則 |
|---|---|---|---|
| `highway=street_lamp`（`lamp`、`lampDouble`） | 街燈 `lamp`：射兩槍熄 10 秒，暗區裏的敵人瞄不到（BLACKOUT） | `fixtures: [x, z, 'lamp']` | 離頭目車輛的路 ≥ 2.5 米；兩盞之間 ≥ 8 米（暗區半徑 4 米，不重疊）；一張圖最多 6 盞 |
| `shop=*`，或 `amenity=restaurant`／`cafe`／`bar`（有 `name`） | 吊招牌 `sign`：射落壓人（CRUSHED） | `fixtures: [x, z, 'sign', facing]` | 掛在店的臨街面中點外；`facing` 是臨街面向外的方向；店名一律換成虛構 |
| `entrance=*`、`door=*`（樓宇輪廓上的點） | 門 `door`：一腳踢開（SLAM） | `fixtures: [x, z, 'door', facing, w, h]` | 寬取 `width`，沒有就 2 米（導航格每邊膨脹 0.5 米，窄過 2 米人走不過）；只取通到可入屋內的 |
| （OSM 沒有鐵閘的標籤） | 鐵閘 `shutter` | `fixtures: [x, z, 'shutter', facing, w, h]` | 開發者手揀 |
| `amenity=bench`（`bench`） | 長椅：矮掩體 | `solids: [x, z, 1.6, 0.5, 0.45, 'bench', facing]` | 按 `direction` 擺；離其他掩體 ≥ 1.5 米 |
| `amenity=waste_basket`、`amenity=recycling`（`bin`） | 垃圾桶：矮掩體 | `solids: [x, z, 0.6, 0.6, 0.9, 'bin']` | 同上 |
| `barrier=bollard`、`barrier=block`（`bollard`、`block`） | 路樁：小掩體 | `solids: [x, z, 0.3, 0.3, 0.9, 'bollard']` | 一排相連的合成一段 |
| `amenity=post_box`（`postBox`） | 郵筒：矮掩體 | `solids: [x, z, 0.6, 0.5, 1.2, 'postbox']` | |
| `highway=bus_stop` 而 `shelter=yes`（`busStop`） | 候車亭：玻璃屏風加頂 | `glass: [...]` | 沒有 shelter 的不取 |
| `amenity=motorcycle_parking` | 一排電單車：矮掩體（澳門街景） | `solids` | 每 1 米一架；模型待做 |
| `highway=traffic_signals`、`highway=crossing`（`signal`、`pedSignal`） | 不入遊戲，只作佈景 | — | |
| `natural=tree` | 樹：佈景，不擋子彈 | `trees` | 已有 |
| `amenity=fountain` | 水：踢落去 SPLASH | `water` | 已有（議事亭噴水池） |
| `emergency=fire_hydrant` | （將來）射爆噴水 | — | 未有系統 |

**流程：**
1. **抽取**：在子專案用 Overpass 抽地圖範圍內的節點，只要上表左欄的標籤，存成 `<子專案>/data/osm_points.json`。座標轉成地圖自己的米制（x 東、y 北）。
2. **轉換**：`scripts/<地圖>-extract.mjs` 用地圖的 `toGame` 轉到遊戲座標，只留可玩範圍內的（外圍 `keep` 米留給佈景），寫進 `src/<地圖>/data.js` 的 `points`。
3. **套表**：地圖資料（`src/maps.js`）按上表把點位變成 `fixtures`、`solids`、`glass`，再和手放的合併。規則欄的過濾（車輛的路、間距、上限）在這一步做。
